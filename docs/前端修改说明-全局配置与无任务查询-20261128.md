# 前端修改说明：全局配置与无任务查询

更新日期：2026-11-28。接口定义以 [Apifox 导入文件](apifox-openapi.yaml) 2.9.2 和当前后端控制器为准。本文列出本次前端需要修改的内容，不引入新的接口字段。

## 1. 本次规则

配置、参数勾选、历史查询、实时查询和 WebSocket 订阅全部不再绑定试验任务。前端不传 `taskId`，也不按当前任务对返回数据再次过滤。

遥测数据和 FEP 文件的写入归属由后端处理：接收时绑定最新运行中的试验任务，没有运行中的任务则不保存新数据。前端不查询、选择或提交这个写入任务编号。

| 对象或页面 | 调整后的行为 |
| --- | --- |
| 采集接口、协议配置 | 全局维护；无需先选择任务即可增删改查、启停 |
| 设备卫星、所属系统、参数解析规则 | 全局维护；按接口返回的主键操作 |
| 处理规则开关、校准通道 | 全局配置；切换任务不切换开关或通道 |
| 参数勾选 | 按场景、目标、设备卫星和遥测代号区分，不按任务区分 |
| 处理后数据、正常帧、异常帧、曲线 | 按接口、参数和时间查询，允许返回不同任务保存的数据 |
| 校准记录、告警、统计 | 不按任务筛选，也不依赖是否存在运行中任务 |
| 可视化窗口 | 继续按登录用户隔离，不再按任务生成多套页面 |
| 图片和文件窗口 | 按窗口和原有分页条件查询，不传任务编号 |
| 试验任务管理、生命周期、任务评估 | 仍按各自接口要求使用任务编号；本次不移除这些业务的任务功能 |

没有运行中任务时，已有历史数据仍然可以查询，配置和窗口仍然可以维护。页面不要因为“未选择任务”或“没有运行中任务”直接返回空数组、清空勾选或禁用操作按钮。

## 2. 请求与页面状态修改清单

1. 移除下表范围内 URL 查询参数、JSON 请求体和上传表单中的 `taskId`。
2. 检查公共请求拦截器，取消对这些接口自动补任务编号的逻辑；不要改为自动查询最新任务后再传编号。
3. 移除这些页面的“请选择任务后查询”校验、任务必填表单项及任务归属校验。
4. 移除“切换任务后清空列表、勾选、窗口或重建遥测订阅”的监听逻辑。
5. 这些页面的请求缓存、勾选缓存、布局缓存及组件状态不再使用任务编号作为区分条件；登录用户、场景、窗口、设备和时间等实际条件仍需保留。
6. 上线时使旧版按任务保存的相关前端缓存失效，重新读取后端数据；不要把多个旧任务缓存直接拼接为新页面。

| 范围 | 代表接口 | 仍需保留的条件 |
| --- | --- | --- |
| 采集管理 | `GET /collection/interfaces`、`GET /collection/protocols`，及对应创建、修改、删除、启停接口 | 业务主键、原筛选条件、分页 |
| 采集与处理统计 | `GET /collection/overview`、`GET /processing/overview`、`GET /processing/realtime` | 各接口原有非任务条件 |
| 设备与系统 | `GET /processing/device-satellites`、`GET /processing/systems`、`GET /processing/rules` | 类型、`deviceSatelliteId`、`systemId`、分页 |
| 参数导入与同步 | `POST /processing/rules/import`、`POST /processing/rules/sync-baseline`、`POST /processing/rules/sync-baseline-devices` | 导入时的 `type`、文件等原有参数 |
| 参数编辑与删除 | `POST /processing/rules/batch-update`、`POST /processing/rules/delete` | 编辑 DTO；删除仍通过查询参数传 `deviceSatelliteId` |
| 参数勾选 | `/processing/telemetry-filter-tree`、`/processing/telemetry-filter-selection/update`、`/processing/telemetry-filter-selection/clear` | 场景、目标及参数身份，见第 3 节 |
| 遥测历史 | `/processing/realtime/telemetry`、`/processing/realtime/invalid`、`/processing/processed`、`/processing/processed/curve` | 接口或勾选范围、遥测类型、时间 |
| 处理开关 | `GET /processing/rule-config`、`POST /processing/rule-config/update` | `parameterRangeCheckEnabled` |
| 校准 | `/calibration/overview`、`/calibration/channels`、`/calibration/records` 及相关详情、写操作 | 通道或记录主键、分页及原筛选条件 |
| 仪表盘与数据告警 | `/dashboard/collection`、`/dashboard/processing`、`/alarms/data` 及详情、状态修改 | 时间范围、告警筛选及主键 |
| 可视化 | `/visualization/widgets`、`/visualization/items/**`、`/visualization/config/**`、`/visualization/widgets/{widgetId}/files` | 窗口或数据项主键、文件、分页；用户身份由登录态确定 |

取消任务条件不代表取消登录或组件归属校验。前端不提交 `userId` 来指定其他用户的页面。

## 3. 参数勾选

### 3.1 场景必须保留

`selectionType` 与 `widgetType` 是两套不同的枚举，不能混用。

| 场景 | `selectionType` | `targetId` | 可视化 `widgetType` |
| --- | --- | --- | --- |
| 处理后数据表格 | `1` | 固定为 `0` | 不适用 |
| 处理后数据曲线 | `2` | 固定为 `0` | 不适用 |
| 可视化实时数据窗口 | `3` | 当前窗口的 `id` | `2`，实时数据 |
| 可视化实时曲线窗口 | `4` | 当前窗口的 `id` | `1`，实时曲线 |

表格与曲线各自保存勾选；不同窗口的勾选各自保存。固定处理页面的勾选是全局共用配置，可视化窗口的勾选受窗口所属用户校验。

### 3.2 筛选树、勾选与清除

```text
GET /processing/telemetry-filter-tree?selectionType=1&targetId=0
GET /processing/telemetry-filter-tree?deviceSatelliteId=12&selectionType=1&targetId=0
GET /processing/telemetry-filter-tree?deviceSatelliteId=12&selectionType=4&targetId=9
```

沿用现有展开层级、`systemId` 和遥测代号搜索方式。`selectionType`、`targetId` 是筛选树请求的必填条件。

勾选或取消：`POST /processing/telemetry-filter-selection/update`。

```json
{
  "parseRuleId": 101,
  "checked": true,
  "selectionType": 1,
  "targetId": 0
}
```

取消时仅将 `checked` 改为 `false`。`parseRuleId` 必须使用当前接口返回的有效参数主键。

清除当前场景：`POST /processing/telemetry-filter-selection/clear`。

```json
{
  "selectionType": 4,
  "targetId": 9
}
```

清除仅作用于指定场景或窗口，不代表清除所有页面的勾选。保存勾选后刷新当前树和数据；若正在订阅表格或曲线，关闭旧连接并重新订阅，让新勾选生效。

### 3.3 参数身份

表格行、曲线系列及前端参数缓存使用“`deviceSatelliteId` + `telemetryCode`”区分参数，外围再保留场景和窗口范围。不同设备可以有相同遥测代号；不要只使用 `telemetryCode`，也不要再拼入任务编号。

## 4. HTTP 查询与数据展示

```text
GET /processing/collect-interfaces?interfaceName=采集
GET /processing/realtime/telemetry?interfaceId=11
GET /processing/realtime/invalid?interfaceId=11
GET /processing/processed?selectionType=1&targetId=0
GET /processing/processed/curve?selectionType=2&targetId=0
GET /processing/processed?selectionType=3&targetId=21
GET /processing/processed/curve?selectionType=4&targetId=9
```

以上主键仅为示例，实际使用列表和筛选树返回值。

### 4.1 接口筛选和时间

正常帧、异常帧通过 `/processing/collect-interfaces` 加载采集接口选项，选项字段为 `interfaceId`、`interfaceName`。查询历史帧仍必须传有效 `interfaceId`，结果最多为最新 100 条。

四个遥测历史接口都支持 `startTime`、`endTime`，格式示例为 `2026-11-28T10:00:00`：

| 时间传法 | 后端行为 |
| --- | --- |
| 都不传 | 查询本次请求时间之前 15 分钟 |
| 只传开始时间 | 结束时间取当前时间 |
| 只传结束时间 | 开始时间取结束时间之前 15 分钟 |
| 两者都传 | 按指定时间范围查询；开始晚于结束时报参数错误 |

历史页面按用户选择的时间查询；实时页面使用 WebSocket。没有新数据时显示实际空值、最后更新时间或空态，不因为任务状态改变而隐藏历史记录。

### 4.2 处理后表格

`GET /processing/processed` 的响应示例：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": [
    {
      "deviceSatelliteId": 12,
      "telemetryCode": "TM001",
      "parameter": "电池电压",
      "parameterValue": 28.5,
      "status": "正常",
      "processTime": "2026-11-28T10:00:00"
    }
  ]
}
```

`parameterValue` 可以是数值、文本或空值。数值 `0` 正常显示；空值显示占位，不用默认零替代，也不要对所有文本执行数值转换。没有勾选时列表可为空；有勾选但查不到采样时，仍可能返回参数名称和空值行。

未配置公式或找不到公式脚本时，后端现在按原码输出数值；已存在脚本执行失败仍可能返回空值。前端不自行补公式、不把空值画成零点，历史失败记录也不会自动补算。

### 4.3 历史曲线

`GET /processing/processed/curve` 的 `data` 元素示例：

```json
{
  "deviceSatelliteId": 12,
  "telemetryCode": "TM001",
  "parameter": "电池电压",
  "times": [1795831200000, 1795831201000],
  "values": [28.5, 28.6]
}
```

`times` 是 Unix 毫秒时间戳，与 `values` 一一对应。该结构用于 HTTP 历史曲线；WebSocket 曲线增量结构见下一节。

## 5. WebSocket

### 5.1 连接和订阅

使用浏览器原生 WebSocket 连接管理服务的 `/ws/telemetry`；沿用现有 API 代理前缀，HTTPS 页面使用 `wss`。连接成功后发送一条订阅 JSON，`accessToken` 使用现有登录令牌，不传 `taskId`。

处理后表格：

```json
{
  "accessToken": "登录令牌",
  "stream": "processed",
  "selectionType": 1,
  "targetId": 0
}
```

可视化曲线：

```json
{
  "accessToken": "登录令牌",
  "stream": "curve",
  "selectionType": 4,
  "targetId": 9
}
```

正常帧：

```json
{
  "accessToken": "登录令牌",
  "stream": "normal",
  "interfaceId": 11
}
```

异常帧将 `stream` 改为 `abnormal`。参数订阅可继续使用可选的 `telemetryType`；表格订阅只配场景 `1` 或 `3`，曲线订阅只配场景 `2` 或 `4`。

每条连接只能发送一次订阅、绑定一个范围。切换接口、遥测类型、场景、窗口或修改勾选后，应关闭旧连接再新建；不要在旧连接上再次发送订阅 JSON。切换试验任务本身不需要重建连接。

### 5.2 接收与重连

| 内容 | 前端处理 |
| --- | --- |
| `type = snapshot` | 接收初始化快照；存在分片时累计到 `complete = true` 再完成初始化 |
| `type = delta` | 按消息及数组顺序处理增量 |
| `sequence` | 仅在当前连接内递增；新连接重新计数 |
| `type = error` | 展示 `message`，按登录或订阅错误处理 |
| 关闭码 `1008` | 检查令牌、请求参数和组件归属，不无限重试无效订阅 |
| 关闭码 `1013` | 表示需要重新同步，可退避后重连并接收新快照 |

页面卸载、用户退出或关闭窗口时，关闭对应连接并清理重连计时器。

表格快照用于初始化勾选行，增量按设备卫星和遥测代号覆盖最新值。曲线先通过 HTTP 取得历史点，再订阅实时增量；曲线订阅的初始快照可以是空数组，不要据此清空已加载的历史曲线。

曲线增量的 `data` 元素与表格参数记录相同，使用 `processTime` 和 `parameterValue`，不是 HTTP 的 `times/values`：

```json
{
  "type": "delta",
  "stream": "curve",
  "sequence": 2,
  "complete": true,
  "retentionSeconds": 259200,
  "data": [
    {
      "deviceSatelliteId": 12,
      "telemetryCode": "TM001",
      "parameter": "电池电压",
      "parameterValue": 28.5,
      "status": "正常",
      "processTime": "2026-11-28T10:00:00"
    }
  ]
}
```

同一毫秒可能收到多个曲线点，按收到顺序逐个追加，不仅按时间戳去重。断线期间可能缺点，前端可标记中断并提供手动历史查询，不假设重连会补发全部历史。

正常帧和异常帧按 `frameId` 合并，按 `frameOrder` 倒序展示；结合 `expiresAt`、`cachedBytes` 和 `frameCapacityBytes` 清理过期或超限帧。正常帧时间字段为 `time`，异常帧为 `receiveTime`；RPC 帧的 `deviceSatelliteId` 可以为空。具体缓存处理沿用[遥测实时对接说明](前端对接-遥测实时轮询.md)。

`retentionSeconds` 使用服务实际返回值，不写死。业务时间字符串按服务约定的 UTC+8 时区解释；`times`、`expiresAt` 已是 Unix 毫秒，不再额外加八小时。

## 6. 可视化窗口与布局

1. 页面加载直接调用 `GET /visualization/widgets`，不先按任务创建或恢复页面。窗口列表是当前登录用户的全局页面。
2. 编辑、拖动、缩放、删除、加载文件和参数勾选使用窗口返回的 `id`；不要使用数组下标或旧任务编号定位窗口。
3. `widgetKey` 仍需在当前用户页面内唯一。窗口标题和类型可以重复，不能据此合并窗口。
4. 删除使用 `POST /visualization/widgets/delete`，JSON 只需要 `id`。删除成功后移除窗口并释放该窗口订阅；失败时保留窗口、展示后端错误信息。
5. 导入导出不传任务编号。导入前先调用 `/visualization/config/import/preview` 检查，再调用 `/visualization/config/import` 导入；两者表单保留 `file`。
6. 导入成功后重新加载窗口列表、筛选树和订阅。导入会生成新窗口主键，不继续使用导入前的 `targetId` 或旧勾选缓存。

```json
{
  "id": 17
}
```

全局化不取消登录权限和窗口所属用户校验。不要通过给请求补任务编号来处理权限失败，也不要新增 `scope_key` 表单项或请求字段。

## 7. 协议与采集接口的启停、删除

| 操作 | 协议配置 | 采集接口 |
| --- | --- | --- |
| 修改启用状态 | `POST /collection/protocols/enabled` | `POST /collection/interfaces/enabled` |
| 删除 | `POST /collection/protocols/delete` | `POST /collection/interfaces/delete` |
| 删除前置条件 | 先禁用；不存在未删除采集接口的绑定 | 先禁用 |

启停请求示例：

```json
{
  "id": 18,
  "enabled": 0
}
```

删除请求只传 `id`，不要把删除按钮绑定到启停接口。协议即使已禁用，只要仍被未删除的采集接口绑定，也会禁止删除，并返回绑定接口名称。

前端应在请求成功后更新状态并刷新列表，保证 `enabled` 和展示名称同步；失败时不要反转开关或修改删除状态。展示后端 `message`，包括“请先禁用协议配置，再执行删除”等具体原因。

提交枚举时使用 `/findData` 返回的 `value`，展示使用 `label` 或对应的中文名称字段。当前启停接口的值仍是数字 `0/1`，不要发送中文标签。

## 8. 全局处理开关、校准与文件展示

处理开关直接查询 `GET /processing/rule-config`。保存使用 `POST /processing/rule-config/update`：

```json
{
  "parameterRangeCheckEnabled": 1
}
```

开关是全局状态，切换任务不重置。新环境默认关闭，前端以接口实际返回值为准，不自行创建数据库配置或提交内部主键。

校准通道、记录、野值详情、告警和统计列表移除任务筛选，保留原有分页、时间、状态、通道等条件。图片和文件窗口调用 `/visualization/widgets/{widgetId}/files` 时只保留窗口和分页条件；如果页面展示数据的任务归属信息，也不据此做当前任务的二次过滤。

## 10. 前端验收清单

- [ ] 未选择任务、没有运行中任务时，可以查询配置、维护窗口并查看已保存历史。
- [ ] 受影响接口的 Query、JSON、FormData 和 WebSocket 首条订阅中均无 `taskId`；公共拦截器不自动补任务。
- [ ] 切换任务不会清空参数勾选、重置全局开关、替换布局或重建已有遥测订阅。
- [ ] 表格与曲线、不同窗口之间的勾选保持独立；四种场景与目标主键传法正确。
- [ ] 保存或清除勾选后刷新数据并重新订阅，新增与取消的参数立即按新范围显示。
- [ ] 相同遥测代号在不同设备下不会互相覆盖，数值零、文本和空值分别正确展示。
- [ ] HTTP 历史曲线按 `times/values` 绘制，实时曲线按 `processTime/parameterValue` 追加，同毫秒多点不丢失。
- [ ] 切换接口会关闭旧帧订阅；页面卸载后不再自动重连；分片快照、空快照和连接中断均可正确处理。
- [ ] 协议和采集接口删除前置条件正确，失败消息可见，删除失败不改变启用状态。
- [ ] 导入配置成功后使用新窗口主键，组件增删改查不依赖任务或处理开关记录。
- [ ] 升级后重新加载服务器数据，不再恢复旧任务分区下的设备、参数及窗口缓存。

本文已按当前控制器、DTO、枚举、返回对象和 WebSocket 实现核对；前端项目修改及浏览器验收由前端对接方执行。
