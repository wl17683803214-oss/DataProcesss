# 全局配置、无任务查询与数据归属

本说明对应 2026-11-27 至 2026-11-28 的规则调整，接口以 `docs/apifox-openapi.yaml` 2.9.2 为准。前端逐项修改、请求示例及验收清单见[前端修改说明](前端修改说明-全局配置与无任务查询-20261128.md)。

## 配置和查询

采集接口、协议配置、设备卫星、所属系统、遥测解析规则、校准通道及参数范围检查开关均全局管理。参数勾选不绑定任务，仍按勾选场景、组件及设备参数区分；可视化布局继续按登录用户隔离。

以下接口不再传入 `taskId`，也不根据当前任务隐式过滤：

- `/collection/**`：接口、协议及采集总览。
- `/processing/**`：设备、规则、导入、系统树、参数勾选、正常帧、异常帧、参数最新值、曲线及处理统计。
- `/calibration/**`：通道配置、校准记录、详情及总览。
- `/dashboard/**`、`/alarms/data`：全局统计及数据告警。
- `/visualization/**`：当前用户布局、导入导出、图片及文件列表。

查询保留原有接口主键、设备卫星主键、参数、组件、用户权限、时间范围和分页约束。时间范围内可以返回不同任务的数据；没有运行中任务时仍可查询之前保存的数据。试验任务列表、生命周期消息及任务评估本身仍使用任务编号。

```text
GET /processing/collect-interfaces?interfaceName=采集
GET /processing/realtime/telemetry?interfaceId=11
GET /processing/realtime/invalid?interfaceId=11
GET /processing/processed?selectionType=1&targetId=0
GET /processing/processed/curve?selectionType=2&targetId=0
GET /processing/telemetry-filter-tree?selectionType=1&targetId=0
GET /calibration/records?pageNum=1&pageSize=20
```

参数勾选示例：

```json
{
  "parseRuleId": 101,
  "checked": true,
  "selectionType": 1,
  "targetId": 0
}
```

WebSocket 订阅不传任务编号，也不跟随任务修改订阅范围。任务切换后，同一接口或参数的新数据继续进入原订阅。

```json
{
  "accessToken": "登录令牌",
  "stream": "normal",
  "interfaceId": 11
}
```

```json
{
  "accessToken": "登录令牌",
  "stream": "processed",
  "selectionType": 1,
  "targetId": 0
}
```

## 写入任务归属

仅遥测数据和 FEP 文件保存任务编号。处理服务启动时查询一次运行中任务，按开始事件时间倒序、任务编号倒序稳定选择最新任务。任务开始或结束事务提交后，管理服务通知 `POST /internal/collection/tasks/refresh` 重查数据库并替换共享缓存。通知异常向生命周期消费者传播，由已有 RocketMQ 消费重试，不增加定期任务核对。

采集接口始终由自己的启用开关控制，任务事件不会启停或重启接口。遥测报文在进入异步处理队列前固定任务编号，帧与参数使用相同归属；FEP 在发送请求到达时固定任务，整个文件接收及后续上传、消息重试沿用该归属，接收目录按接口和任务隔离，避免不同任务的同名文件被当作重传。

没有运行中任务时，遥测仍可完成解析、校准和全局统计，但不写遥测存储、实时缓存或发送无归属遥测消息。FEP 新文件请求返回协议中的接收方不可用，不创建临时文件或文件记录。任务结束前已经开始处理的报文和文件继续按原任务完成保存。

校准记录、野值详情、数据告警及采集处理统计不记录任务归属。采集速率、处理速率及样本缓存采用全局范围；切换任务不会清空这些累计量。

## 数据结构升级

新库使用更新后的 `sql/system.sql` 和 `sql/business_schema.sql`。全局处理开关固定使用 `processing_rule_config.id = 1`，不再增加作用范围字段。建表SQL包含 `INSERT` 默认记录，野值检测默认关闭；重复执行不覆盖已经设置的开关。已有数据库应先完成升级，再启动新版本处理服务。

升级语句集中在 `GlobalResourceMigrationMapper.xml`，由事务组件执行，不在业务 Java 中拼接 SQL。停止旧版实例后，可在管理服务的一次升级启动中设置环境变量 `DATA_PROCESSING_MIGRATE_GLOBAL_RESOURCES=true`，或在其 `data-processing` 配置下显式设置 `migrate-global-resources: true` 并写明一次升级用途。成功后移除该选项，再启动处理服务和正常业务流量。

升级先锁定相关表并检查设备编码、校准公式、用户组件键、参数勾选及统计窗口冲突。存在冲突则返回中文身份信息并整体回滚，不自动删除已有配置。全局开关优先继承旧版 `scope_key = 'global'` 记录的值；未添加过该字段时保留主键一的值，主键一不存在时采用最近更新的旧配置，无旧配置时关闭。随后删除旧范围列，原配置行保留，固定主键一作为唯一生效记录。已完成全局化的环境可在锁定配置表的事务内单独执行映射中的 `migrateProcessingRuleConfig`，不必重复调整其他表。

组件增删、参数勾选、参数表替换及整页导入共用独立的数据库事务锁，事务结束自动释放。锁不再查询处理规则配置表，因此即使开关尚未初始化，可视化组件仍可正常维护；配置导出和检查也不依赖处理开关记录。

历史配置的 `task_id` 列保留作为兼容信息，新代码不读写、不筛选这些字段。全局唯一约束不再包含任务。遥测表、遥测分表目录及 FEP 接收记录中的任务字段和写入唯一键保持，用于追溯数据接收归属。

实时缓存改用不含任务的 `parameter:v2`、`frame:v2` 和 `selection:union:v2` 键。旧缓存按原有过期时间回收，新缓存随新数据生成；升级后实时快照不会自动回填旧任务分区的数据，历史数据仍可通过查询接口读取。切换版本前应让旧实例完成已有统计窗口及校准待写队列。
