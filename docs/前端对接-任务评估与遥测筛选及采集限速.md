# 前端对接：任务评估、遥测筛选、采集接口配置与Lua公式管理

本文包含试验任务评估、处理后遥测及曲线的类型筛选、采集接口名称筛选框、UDP/TCP接收限速、图片分辨率和Lua公式管理。Lua公式的分页查询、覆盖导入、批量删除、试算及运行快照同步见第8节。地址沿用现有网关前缀与登录认证方式，Apifox导入文件为 `docs/apifox-openapi.yaml`。

## 1. 通用约定

- 响应使用 `code`、`message`、`data`，成功时 `code=200`；无数据时可能省略 `data`。
- 参数错误返回HTTP 400，响应体 `code=400`，页面展示中文 `message`，同时处理请求失败分支。
- 下拉框显示 `label`，提交 `value`。以下仅含新增字段的请求片段不能替代原有完整请求。

## 2. 试验任务评估

### 页面与查询

试验任务列表或详情增加“试验任务评估”，读取 `GET /experiment/tasks` 返回的任务数组，每条任务新增 `taskEvaluation` 字符串，空值显示“未评估”。`taskId` 为字符串。

增加“评估”操作，弹窗使用多行文本框，编辑回填已有评估。保存前去除首尾空白，内容不能为空；提交期间禁用保存按钮，成功后关闭弹窗并刷新任务数据。不限制任务状态，再次保存覆盖原评估，不保存评估历史；不支持用空内容清除评估。

### 保存接口

`POST /experiment/tasks/evaluate`，JSON请求：

```json
{
  "taskId": "TASK-20260908-001",
  "taskEvaluation": "试验数据完整，任务执行符合预期。"
}
```

两字段必填且不能全为空白，任务编号最多100个字符。成功响应：

```json
{
  "code": 200,
  "message": "操作成功"
}
```

常见错误：“试验任务编号不能为空”“试验任务评估不能为空”“试验任务不存在”。后台任务开始、结束消息不会覆盖手动评估。

## 3. 处理后遥测和曲线增加类型筛选

### 枚举

调用 `GET /processing/findData`，从 `data.telemetryType` 读取：

```json
[
  { "value": "TM_TYPE_UNSPECIFIED", "label": "未指定" },
  { "value": "TM_TYPE_REAL_TM", "label": "实时遥测" },
  { "value": "TM_TYPE_DELAY_TM", "label": "延时遥测" },
  { "value": "TM_TYPE_MEMORY_TM", "label": "存储遥测" },
  { "value": "TM_TYPE_DEVICE_TM", "label": "设备遥测" }
]
```

对应Proto的 `TelemetryType tm_type = 7`，提交英文枚举名。前端增加“全部”选项，选择全部或清空时不传参数；`TM_TYPE_UNSPECIFIED` 只筛选未指定类型，不能代替全部。

### 请求

两个接口均增加可选字符串查询参数 `telemetryType`，不传或留空查询全部，非法值返回“遥测类型不正确”。

| 接口 | selectionType | targetId |
| --- | --- | --- |
| GET /processing/processed | 1处理后表格、3可视化表格，默认1 | 场景1为0；场景3为组件widgetId |
| GET /processing/processed/curve | 2处理后曲线、4可视化曲线，默认2 | 场景2为0；场景4为组件widgetId |

两接口都必传 `taskId`，现有参数勾选与任务、设备卫星范围继续生效。

```text
GET /processing/processed?taskId=TASK-20260908-001&selectionType=1&targetId=0&telemetryType=TM_TYPE_REAL_TM
GET /processing/processed/curve?taskId=TASK-20260908-001&selectionType=2&targetId=0&telemetryType=TM_TYPE_DELAY_TM
```

### 页面与返回

- 表格、曲线增加“遥测类型”下拉框，默认全部，切换后重新请求；自动刷新继续携带当前条件。
- 快速切换时避免旧请求覆盖新结果，清空后移除参数。
- 后端先筛选类型，再取最新记录或最近120个数值有效曲线点，不在前端过滤当前结果。
- 无匹配数据时仍返回已勾选参数身份，表格值为空，曲线 `times`、`values` 为空数组；应清除旧数据。
- 表格 `parameterValue` 支持数值、字符串或空值；曲线 `times` 是毫秒时间戳，与数值数组 `values` 一一对应，按时间升序返回。
- 记录本身不新增遥测类型展示字段，选项从枚举接口读取。

## 4. 采集接口增加名称筛选框

后端已支持。采集接口列表查询区域增加“采集接口名称”输入框，提示“请输入采集接口名称”，提交至 `GET /collection/interfaces` 的可选查询参数 `interfaceName`。

```text
GET /collection/interfaces?taskId=TASK-20260908-001&interfaceName=遥测&pageNum=1&pageSize=10
```

- 按包含关系查询，“遥测”可匹配“遥测UDP接口”。首尾空格会去除，不传或全为空白时不限名称。
- 点击查询或按回车时，将 `pageNum` 重置为1，携带名称与现有其他条件请求。中文参数交由现有请求库编码。
- 清空或重置时移除名称参数并回到第一页；翻页保留名称条件。
- 后端完成筛选与总数统计，不要只过滤当前页数据。记录为 `data.records`，总数为 `data.total`，分页信息为 `data.pageNum`、`data.pageSize`，单页最多100条。

## 5. UDP/TCP接收限速

### 表单、枚举与字段

仅 `transferType=1`（UDP）或2（TCP）展示“接收速率上限”数值框和单位下拉框，不增加限速开关，提示“留空表示不限速”。

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| receiveRateLimit | number / null | 大于0且不超过1000000，最多三位小数；不传或null不限速 |
| receiveRateLimitUnit | string / null | 配置上限时必填，提交英文单位编码 |
| receiveRateLimitUnitName | string / null | 响应中的显示标签，KB/s或MB/s，不作为保存参数 |

通过 `GET /collection/findData` 的 `data.receiveRateLimitUnit` 获取：

```json
[
  { "value": "kilobytes_per_second", "label": "KB/s" },
  { "value": "megabytes_per_second", "label": "MB/s" }
]
```

1 KB为1024字节，1 MB为1024 KB。单位沿用已有速率枚举。

### 保存和回显

现有 `POST /collection/interfaces/create`、`POST /collection/interfaces/update` 的JSON请求增加下列字段，其他必填参数保持原约定。配置100 KB/s的新增字段片段：

```json
{
  "receiveRateLimit": 100,
  "receiveRateLimitUnit": "kilobytes_per_second"
}
```

取消限速的字段片段：

```json
{
  "receiveRateLimit": null,
  "receiveRateLimitUnit": null
}
```

- 更新时不传上限也会取消原有限速，编辑表单必须回填并提交原配置。
- 列表 `GET /collection/interfaces`、详情 `GET /collection/interfaces/{id}` 及保存结果返回数值、英文单位、单位标签。列表可增加“接收速率上限”列，空值显示“不限速”，非空显示如“100 KB/s”。
- 上限为空时后台清空单位。切换到HTTP时隐藏限速输入项并将两字段置为null，HTTP提交非空上限会报“只有UDP和TCP接口支持接收限速”。
- 限速配置与原有实时速率 `interfaceRateKbps` 分别展示，不要混用。
- 后台提交后异步同步，限速值或单位变化会重启对应监听，当前TCP连接可能断开，发送端需支持重连。

### 向用户说明的限制行为

- TCP额度不足时暂停应用读取，通过流量控制让发送方逐步减速，不主动丢弃已读取的数据。
- UDP额度不足时丢弃整个超限报文，不进入后续处理和入库。页面明确提示“UDP超限会丢包”，单播和组播规则相同。
- 按套接字载荷字节计费，不包含网络链路头；TCP包含应用传输头和协议控制数据，发送响应不受限速影响。
- 每个接口独立限速，重连不重置当前接口额度，接口重启会重建额度。
- 采用令牌桶，TCP最多积累一秒额度，UDP至少可容纳65535字节，避免低速配置永远收不到单个大包。因此允许有限突发，并非每个自然秒严格截断。UDP仍会到达网卡，限速控制进入后续处理的数据量。
- FEP等带发送端等待超时的协议在低速配置下可能超时，联调需结合实际报文长度与对端超时设置。

## 7. 图片文件分辨率

`GET /visualization/widgets/{widgetId}/files` 的 `data.records` 每条记录新增可空字符串字段 `resolution`，例如 `"1920×1080"`，表示原始图片宽×高，单位为像素；分隔符为乘号 `×`。原有请求参数、分页结构及文件签名地址规则不变。

图片组件的文件信息区域或列表增加“分辨率”展示，直接展示返回字符串，空值显示“—”；普通文件不必展示该列。示例字段片段：

```json
{
  "fileName": "载荷图像001.png",
  "fileType": "png",
  "resolution": "1920×1080"
}
```

分辨率由后端在完整文件接收后读取图片头并保存，无需前端填写或额外请求图片获取尺寸；不是页面缩放尺寸，也不是打印DPI。多帧图片读取第一帧尺寸，不应用EXIF方向旋转。

非图片、无法识别的图片、当前运行环境缺少解码器的格式及历史未识别记录返回null，不影响原有接收、上传和文件展示流程。使用Java自带ImageIO读取，未额外引入格式插件；Java 8默认通常可读取JPEG、PNG、GIF、BMP，WebP及TIFF等格式取决于实际运行环境的解码器，未支持时保持空值。历史数据不自动回填。

已有数据库先执行 `sql/20261029_add_file_resolution.sql`，管理服务和处理服务配套部署。验收覆盖正常图片、普通文件、损坏图片、不支持格式和历史记录，确认分辨率展示及空值处理；数据库迁移与真实文件上传联调尚未执行。

## 8. Lua公式管理（2026-10-30）

Lua改动已另行整理为[独立前端对接文档](前端对接-Lua脚本公式管理.md)，交接前端时使用该文档；下方保留原有说明供查阅。

### 页面与数据规则

公式在全系统共享，接口不传taskId。一个公式编号只保存一份脚本，同编号导入直接覆盖当前源码，没有历史版本，也没有启用、停用状态。公式编号使用字符串传递和展示，不转成数字，避免丢失前导零。

页面提供编号、名称筛选，列表展示编号、名称、首次导入时间、最近修改时间；操作包括导入、单个导出、勾选导出、批量删除、试算和“同步运行配置”。不增加版本列、历史版本入口或启停开关。列表不包含源码，下载源码使用导出接口。

### 接口一览

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | /processing/formulas | 分页查询，支持编号和名称筛选 |
| POST | /processing/formulas/import | 上传单个Lua文件或ZIP，同编号覆盖 |
| GET | /processing/formulas/export | 下载指定编号的当前脚本 |
| GET | /processing/formulas/export-zip | 下载指定编号或全部当前脚本 |
| POST | /processing/formulas/batch-delete | 按编号批量删除，整批校验引用 |
| POST | /processing/formulas/preview | 使用数据库当前脚本试算 |
| POST | /processing/formulas/sync | 提交后台运行配置同步 |

### 分页查询与列表绑定

请求示例：`GET /processing/formulas?pageNum=1&pageSize=20&code=109&name=浮点`。

| 查询参数 | 必填 | 说明 |
| --- | --- | --- |
| code | 否 | 公式编号精确匹配，空白表示不筛选 |
| name | 否 | 公式名称模糊匹配，空白表示不筛选 |
| pageNum | 否 | 默认1，必须大于0 |
| pageSize | 否 | 默认20，范围1至200 |

两种筛选同时传入时同时生效。修改或清空筛选条件后将pageNum重置为1。列表绑定data.records，分页总数绑定data.total，不使用records.length代替总数。

成功响应示例：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "pageNum": 1,
    "pageSize": 20,
    "total": 1,
    "records": [
      {
        "code": "109",
        "name": "浮点源码线性转换",
        "createTime": "2026-10-30T10:00:00",
        "updateTime": "2026-10-30T10:20:00"
      }
    ]
  }
}
```

createTime是首次导入时间，覆盖导入保留；updateTime是当前内容最近修改时间。没有version或source字段。时间按接口现有日期时间展示规则处理，不自行附加UTC偏移。列表行键和勾选键均使用code。

### 导入与覆盖

`POST /processing/formulas/import`，使用multipart/form-data，文件字段名为file。浏览器使用FormData提交并自动生成边界，不手写multipart边界。沿用当前登录凭证。

- 接收单个.lua或.zip；源码要求UTF-8。
- 上传文件最大8MB，单个脚本最大64KB。
- ZIP只包含Lua文件，最多100个公式及200个压缩条目；同一包内公式编号不能重复。
- 以脚本内部code作为公式编号，不根据文件名猜测编号。
- 任一脚本校验失败，整批不保存，页面展示中文错误message。
- 同编号导入直接覆盖，不保留历史。导入区明确提示“同编号将覆盖当前脚本；运行接口需要同步配置后生效”。
- 相同源码重复导入不会新增记录或改变更新时间。

成功响应的data是公式元数据数组，每项包含code、name、createTime、updateTime，不是分页对象。导入成功后刷新列表和勾选状态，并提示“导入成功，运行配置尚需同步”；不要将导入成功显示为正在运行的脚本已经更新。

可导入示例包：[处理公式示例.zip](lua-formulas/处理公式示例.zip)，脚本协议和字节序说明见[公式使用说明](lua-formulas/README.md)。

### 单个与批量导出

- 单个：`GET /processing/formulas/export?code=109`，下载当前源码，文件名109.lua。
- 勾选导出：`GET /processing/formulas/export-zip?codes=100,109`，codes按逗号分隔传入；下载文件名formulas.zip。
- 不传codes表示导出全部当前公式，不是只导出当前页。总数量超过100时需按编号选择导出。
- 单次导出1至100个公式；指定任一不存在编号则失败。无勾选时禁用“勾选导出”，避免空codes被误解为导出全部。
- 不再传version，不提供历史脚本下载。

成功响应是文件二进制，不是ApiResponse。前端使用二进制下载方式并带登录凭证；若跨域环境不能读取Content-Disposition，可使用以上已知文件名。失败仍为HTTP 400及JSON错误响应，二进制请求失败分支需要读取JSON中的message，不能把错误JSON保存为.lua或.zip。

### 批量删除

`POST /processing/formulas/batch-delete`，JSON请求：

```json
{
  "codes": ["100", "109"]
}
```

单次提交1至100项，编号为1至20位数字组成的字符串；重复编号只计算一次。前端无勾选时禁用删除按钮，提交期间防止重复请求。服务端规则：

1. 检查整批编号是否存在。
2. 检查是否被任意任务的未删除参数解析配置引用，不限当前页面所选任务。
3. 任一编号不存在或被引用，整批不删除，返回HTTP 400，message列出对应编号。
4. 全部满足条件时删除，事务提交后自动提交后台配置同步。

成功示例：

```json
{"code":200,"message":"操作成功","data":2}
```

data是实际删除数量，不是数组或布尔值。成功后清空已删除行的勾选并重新查询；若删除后当前页为空且pageNum大于1，回到前一页查询。失败时不要先从页面移除部分行，展示服务端message并允许刷新列表。

错误示例：

```json
{"code":400,"message":"以下公式被参数配置引用，整批未删除：109"}
```

删除成功后的页面提示应包含“已删除，运行配置同步已提交”。后台同步是异步操作，响应不表示内存快照已经刷新；已开始处理的帧仍完成原快照，不需要前端重复调用同步接口。

### 公式试算

`POST /processing/formulas/preview`，JSON请求：

```json
{
  "code": "109",
  "rawHex": "3F 80 00 00",
  "bitWidth": 32,
  "processParam": "2/3"
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| code | 是 | 已导入的公式编号，字符串 |
| rawHex | 是 | 每两位十六进制字符表示一个字节，允许空白分隔；文本最长196608字符 |
| bitWidth | 是 | 原码有效位宽，1至524288，字节数必须等于位宽除以8向上取整 |
| processParam | 否 | 按顺序用斜线分隔的数值参数，最长8192字符、最多256项，空值由脚本采用默认规则 |

原码按报文字段取位后的顺序输入，不在前端再次反转；非整字节字段的末字节未用高位必须为零。不要把原码先转成JavaScript数字，避免改变字节顺序或丢失64位精度。没有version入参。

成功响应示例：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "code": "109",
    "valueType": "单精度",
    "value": 5.0,
    "valueText": "5"
  }
}
```

valueType已经是中文展示名称，直接展示，不再按英文枚举二次映射。value为数值或null，valueText为展示文本；页面优先展示valueText，空值显示“—”，不能用真假判断隐藏数值0。试算返回小数位修约前的结果，真实遥测输出还会应用参数配置的decimalPlaces。

试算采用数据库中当前脚本，不代表运行接口当前快照已经同步。试算失败只向当前请求返回中文错误，不生成生产处理告警。

### 参数配置与运行快照同步

参数解析配置中的formulaType填写公式编号，processParam按位置传入；formulaDesc仅保留历史描述，不再参与本地公式计算。formulaType允许null或空字符串，此时正常输出原码，不因无公式而告警。编辑已有参数时仍需保留并提交原接口要求的其他业务字段。

公式选择器可用分页查询接口按编号或名称搜索；不能只加载第一页就认定其他编号不存在，也不要只提供固定的300至303编号。导入包中的100、109、300、301、302、303只是示例公式，均需先导入才能使用。

`POST /processing/formulas/sync` 无请求体，成功响应：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": "公式配置同步已提交，完成情况请查看运行日志和告警"
}
```

页面仅提示“同步已提交”，不能提示“同步已完成”。目前没有专用的同步进度或完成状态查询接口，不新增轮询假定。

运行规则：

- 接口启动或配置同步时查询数据库、编译并加载公式快照，逐帧处理不查询数据库。
- 覆盖导入后，运行接口继续使用原快照，完成同步或重新启动接口后才使用更新脚本。
- 删除成功会自动提交后台同步；同步失败时现有运行快照继续保留，完成情况通过现有运行日志和告警查看。
- 配置有编号但无脚本、参数无效或脚本失败时，当前参数保留二进制原码并产生“参数处理失败”告警，同帧其他参数继续。
- 失败参数没有有效计算值，处理后页面的空值显示“—”，不能强制转换成0；修正并同步后，后续计算正常会自动恢复告警，历史失败数据不自动补算。
