# 前端对接：任务评估、遥测筛选、采集接口配置与Lua公式管理

本文包含试验任务评估、处理后遥测及曲线的类型筛选、采集接口名称筛选框、UDP/TCP接收限速、图片分辨率和Lua公式管理。Lua公式的分页查询、覆盖导入、批量删除及关联遥测参数见第8节链接的独立对接文档。地址沿用现有网关前缀与登录认证方式，Apifox导入文件为 `docs/apifox-openapi.yaml`。

## 1. 通用约定

- 响应使用 `code`、`message`、`data`，成功时 `code=200`；无数据时可能省略 `data`。
- 参数错误返回HTTP 400，响应体 `code=400`，页面展示中文 `message`，同时处理请求失败分支。
- 下拉框显示 `label`，提交 `value`。以下仅含新增字段的请求片段不能替代原有完整请求。

## 2. 试验任务评估

### 页面与查询

试验任务列表或详情增加“试验任务评估”，读取 `GET /experiment/tasks` 返回的任务数组，每条任务新增 `taskEvaluation` 字符串，空值显示“未评估”。`taskId` 为字符串。

增加“评估”操作，弹窗使用多行文本框，编辑回填已有评估。保存前去除首尾空白，内容不能为空；提交期间禁用保存按钮，成功后关闭弹窗并刷新任务数据。不限制任务状态，再次保存覆盖原评估，不保存评估历史；不支持用空内容清除评估。

### 保存接口

`POST /experiment/tasks/evaluate`，JSON请求：

```json
{
  "taskId": "TASK-20260908-001",
  "taskEvaluation": "试验数据完整，任务执行符合预期。"
}
```

两字段必填且不能全为空白，任务编号最多100个字符。成功响应：

```json
{
  "code": 200,
  "message": "操作成功"
}
```

常见错误：“试验任务编号不能为空”“试验任务评估不能为空”“试验任务不存在”。后台任务开始、结束消息不会覆盖手动评估。

## 3. 处理后遥测和曲线增加类型筛选

### 枚举

调用 `GET /processing/findData`，从 `data.telemetryType` 读取：

```json
[
  { "value": "TM_TYPE_UNSPECIFIED", "label": "未指定" },
  { "value": "TM_TYPE_REAL_TM", "label": "实时遥测" },
  { "value": "TM_TYPE_DELAY_TM", "label": "延时遥测" },
  { "value": "TM_TYPE_MEMORY_TM", "label": "存储遥测" },
  { "value": "TM_TYPE_DEVICE_TM", "label": "设备遥测" }
]
```

对应Proto的 `TelemetryType tm_type = 7`，提交英文枚举名。前端增加“全部”选项，选择全部或清空时不传参数；`TM_TYPE_UNSPECIFIED` 只筛选未指定类型，不能代替全部。

### 请求

两个接口均增加可选字符串查询参数 `telemetryType`，不传或留空查询全部，非法值返回“遥测类型不正确”。

| 接口 | selectionType | targetId |
| --- | --- | --- |
| GET /processing/processed | 1处理后表格、3可视化表格，默认1 | 场景1为0；场景3为组件widgetId |
| GET /processing/processed/curve | 2处理后曲线、4可视化曲线，默认2 | 场景2为0；场景4为组件widgetId |

两接口都必传 `taskId`，现有参数勾选与任务、设备卫星范围继续生效。

```text
GET /processing/processed?taskId=TASK-20260908-001&selectionType=1&targetId=0&telemetryType=TM_TYPE_REAL_TM
GET /processing/processed/curve?taskId=TASK-20260908-001&selectionType=2&targetId=0&telemetryType=TM_TYPE_DELAY_TM
```

### 页面与返回

- 表格、曲线增加“遥测类型”下拉框，默认全部，切换后重新请求；自动刷新继续携带当前条件。
- 快速切换时避免旧请求覆盖新结果，清空后移除参数。
- 后端先筛选类型，再取最新记录或最近120个数值有效曲线点，不在前端过滤当前结果。
- 无匹配数据时仍返回已勾选参数身份，表格值为空，曲线 `times`、`values` 为空数组；应清除旧数据。
- 表格 `parameterValue` 支持数值、字符串或空值；曲线 `times` 是毫秒时间戳，与数值数组 `values` 一一对应，按时间升序返回。
- 记录本身不新增遥测类型展示字段，选项从枚举接口读取。

## 4. 采集接口增加名称筛选框

后端已支持。采集接口列表查询区域增加“采集接口名称”输入框，提示“请输入采集接口名称”，提交至 `GET /collection/interfaces` 的可选查询参数 `interfaceName`。

```text
GET /collection/interfaces?taskId=TASK-20260908-001&interfaceName=遥测&pageNum=1&pageSize=10
```

- 按包含关系查询，“遥测”可匹配“遥测UDP接口”。首尾空格会去除，不传或全为空白时不限名称。
- 点击查询或按回车时，将 `pageNum` 重置为1，携带名称与现有其他条件请求。中文参数交由现有请求库编码。
- 清空或重置时移除名称参数并回到第一页；翻页保留名称条件。
- 后端完成筛选与总数统计，不要只过滤当前页数据。记录为 `data.records`，总数为 `data.total`，分页信息为 `data.pageNum`、`data.pageSize`，单页最多100条。

## 5. UDP/TCP接收限速

### 表单、枚举与字段

仅 `transferType=1`（UDP）或2（TCP）展示“接收速率上限”数值框和单位下拉框，不增加限速开关，提示“留空表示不限速”。

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| receiveRateLimit | number / null | 大于0且不超过1000000，最多三位小数；不传或null不限速 |
| receiveRateLimitUnit | string / null | 配置上限时必填，提交英文单位编码 |
| receiveRateLimitUnitName | string / null | 响应中的显示标签，KB/s或MB/s，不作为保存参数 |

通过 `GET /collection/findData` 的 `data.receiveRateLimitUnit` 获取：

```json
[
  { "value": "kilobytes_per_second", "label": "KB/s" },
  { "value": "megabytes_per_second", "label": "MB/s" }
]
```

1 KB为1024字节，1 MB为1024 KB。单位沿用已有速率枚举。

### 保存和回显

现有 `POST /collection/interfaces/create`、`POST /collection/interfaces/update` 的JSON请求增加下列字段，其他必填参数保持原约定。配置100 KB/s的新增字段片段：

```json
{
  "receiveRateLimit": 100,
  "receiveRateLimitUnit": "kilobytes_per_second"
}
```

取消限速的字段片段：

```json
{
  "receiveRateLimit": null,
  "receiveRateLimitUnit": null
}
```

- 更新时不传上限也会取消原有限速，编辑表单必须回填并提交原配置。
- 列表 `GET /collection/interfaces`、详情 `GET /collection/interfaces/{id}` 及保存结果返回数值、英文单位、单位标签。列表可增加“接收速率上限”列，空值显示“不限速”，非空显示如“100 KB/s”。
- 上限为空时后台清空单位。切换到HTTP时隐藏限速输入项并将两字段置为null，HTTP提交非空上限会报“只有UDP和TCP接口支持接收限速”。
- 限速配置与原有实时速率 `interfaceRateKbps` 分别展示，不要混用。
- 后台提交后异步同步，限速值或单位变化会重启对应监听，当前TCP连接可能断开，发送端需支持重连。

### 向用户说明的限制行为

- TCP额度不足时暂停应用读取，通过流量控制让发送方逐步减速，不主动丢弃已读取的数据。
- UDP额度不足时丢弃整个超限报文，不进入后续处理和入库。页面明确提示“UDP超限会丢包”，单播和组播规则相同。
- 按套接字载荷字节计费，不包含网络链路头；TCP包含应用传输头和协议控制数据，发送响应不受限速影响。
- 每个接口独立限速，重连不重置当前接口额度，接口重启会重建额度。
- 采用令牌桶，TCP最多积累一秒额度，UDP至少可容纳65535字节，避免低速配置永远收不到单个大包。因此允许有限突发，并非每个自然秒严格截断。UDP仍会到达网卡，限速控制进入后续处理的数据量。
- FEP等带发送端等待超时的协议在低速配置下可能超时，联调需结合实际报文长度与对端超时设置。

## 7. 图片文件分辨率

`GET /visualization/widgets/{widgetId}/files` 的 `data.records` 每条记录新增可空字符串字段 `resolution`，例如 `"1920×1080"`，表示原始图片宽×高，单位为像素；分隔符为乘号 `×`。原有请求参数、分页结构及文件签名地址规则不变。

图片组件的文件信息区域或列表增加“分辨率”展示，直接展示返回字符串，空值显示“—”；普通文件不必展示该列。示例字段片段：

```json
{
  "fileName": "载荷图像001.png",
  "fileType": "png",
  "resolution": "1920×1080"
}
```

分辨率由后端在完整文件接收后读取图片头并保存，无需前端填写或额外请求图片获取尺寸；不是页面缩放尺寸，也不是打印DPI。多帧图片读取第一帧尺寸，不应用EXIF方向旋转。

非图片、无法识别的图片、当前运行环境缺少解码器的格式及历史未识别记录返回null，不影响原有接收、上传和文件展示流程。使用Java自带ImageIO读取，未额外引入格式插件；Java 8默认通常可读取JPEG、PNG、GIF、BMP，WebP及TIFF等格式取决于实际运行环境的解码器，未支持时保持空值。历史数据不自动回填。

已有数据库先执行 `sql/20261029_add_file_resolution.sql`，管理服务和处理服务配套部署。验收覆盖正常图片、普通文件、损坏图片、不支持格式和历史记录，确认分辨率展示及空值处理；数据库迁移与真实文件上传联调尚未执行。
