# 遥测 WebSocket 前端对接

## 页面调用

| 页面 | 首次加载 | 后续更新 |
| --- | --- | --- |
| 处理后参数表格 | 订阅 `processed`，等待缓存快照 | 按设备卫星主键和遥测代号覆盖最新值 |
| 遥测曲线 | 调用 `GET /processing/processed/curve`，画出历史曲线后订阅 `curve` | 按收到的批次顺序逐点追加 |
| 正常帧 | 选中采集接口，订阅 `normal`，接收缓存快照 | 接收新增正常帧 |
| 异常帧 | 选中采集接口，订阅 `abnormal`，接收缓存快照 | 接收新增异常帧 |

历史查询继续使用四个 HTTP 接口。历史曲线缺省查最近 15 分钟，历史正常帧和异常帧必须传正整数 `interfaceId`。正常帧、异常帧页面首次进入和重连时直接读取 WebSocket 快照。

| 方法和地址 | 用途 |
| --- | --- |
| `GET /processing/processed` | 按时间范围查询勾选参数的最新值 |
| `GET /processing/processed/curve` | 按时间范围查询历史曲线 |
| `GET /processing/realtime/telemetry` | 查询指定接口的历史正常帧 |
| `GET /processing/realtime/invalid` | 查询指定接口的历史异常帧 |

四个历史接口都必传 `taskId`，都可传 `startTime` 和 `endTime`。表格和曲线的历史查询还可传 `selectionType`、`targetId` 和 `telemetryType`。普通曲线页面首次加载的请求示例为 `GET /processing/processed/curve?taskId=TASK001&selectionType=2&targetId=0`。

三个旧的 `/live` HTTP 地址由 `/ws/telemetry` 统一提供实时数据。

## 建立连接

连接管理服务的 `ws://主机/ws/telemetry`，HTTPS 页面使用对应的 `wss://`。使用浏览器原生 WebSocket。打开连接后发送一条订阅 JSON，`accessToken` 使用现有登录令牌。

正常帧订阅示例

```json
{
  "accessToken": "登录令牌",
  "taskId": "TASK001",
  "stream": "normal",
  "interfaceId": 11
}
```

异常帧使用 `stream=abnormal`。正常帧和异常帧的筛选框只列出具体采集接口，移除「全部采集接口」选项。未选接口时显示「请选择采集接口」，等用户选中有效接口后再发起实时订阅或历史查询。切换接口时关闭旧连接，清空旧列表，再订阅新接口。

接口下拉选项通过 `GET /processing/collect-interfaces` 获取。用返回的 `data[].interfaceName` 展示名称，用 `data[].interfaceId` 发起查询和订阅。按名称搜索时可传 `interfaceName`。两个帧页面均使用单选。

曲线订阅示例

```json
{
  "accessToken": "登录令牌",
  "taskId": "TASK001",
  "stream": "curve",
  "selectionType": 2,
  "targetId": 0,
  "telemetryType": "TM_TYPE_DEVICE_TM"
}
```

参数表格使用 `stream=processed`。勾选仍使用现有接口保存。表格场景的 `selectionType` 为 1 或 3，曲线为 2 或 4。1 和 2 的 `targetId` 为 0，3 和 4 使用当前用户在任务下的对应组件主键。未传 `telemetryType` 时订阅所有遥测类型。历史曲线和实时曲线使用相同的勾选范围与类型筛选。

| `selectionType` | 对应页面 | `targetId` |
| --- | --- | --- |
| 1 | 处理后参数表格 | 0 |
| 2 | 处理后参数曲线 | 0 |
| 3 | 可视化表格 | 表格组件主键 |
| 4 | 可视化曲线 | 曲线组件主键 |

更新勾选时先通过 `POST /processing/telemetry-filter-selection/update` 保存，再用对应的任务和场景重新订阅。前端选中的遥测类型可从 `GET /processing/findData` 的 `data.telemetryType` 取值，提交选项的英文 `value`。

一条连接订阅一个范围。多个页面或组件可分别连接。勾选、任务、类型、接口或组件变化后重新订阅。较大的主键可用十进制字符串传入。登录和 HTTP 查询继续使用现有请求封装。

## 消息格式

服务端先发 `type=snapshot`，再发 `type=delta`。快照较大时会拆成多条，前端累积到 `complete=true` 后再整体替换。曲线收到空快照表示订阅生效，保留已画出的历史点。增量也可能拆分，按消息顺序应用即可。

`sequence` 从每个连接的 1 开始递增。下例为正常帧初始快照。

```json
{
  "type": "snapshot",
  "stream": "normal",
  "sequence": 1,
  "complete": true,
  "retentionSeconds": 259200,
  "frameCapacityBytes": 4194304,
  "data": [
    {
      "frameId": "c97c239c-a2eb-4864-8298-ddfdc97d9cf3",
      "frameOrder": 1794209412123000,
      "expiresAt": 1794468612123,
      "cachedBytes": 290,
      "deviceSatelliteId": 123,
      "time": "2026-11-09T15:30:12.123",
      "deviceSatelliteName": "通道一_设备A",
      "channelName": "通道一",
      "rawLength": 6,
      "rawFrame": "01 02 03 04 05 06",
      "checkResultName": "正常"
    }
  ]
}
```

异常帧时间字段为 `receiveTime`，`checkResultName` 为“异常”。正常帧时间字段为 `time`。RPC 卫星帧的 `deviceSatelliteId` 可以为空。

表格和曲线的 `data` 元素使用以下字段。

```json
{
  "deviceSatelliteId": 123,
  "telemetryCode": "TM001",
  "parameter": "电池电压",
  "parameterValue": 28.5,
  "status": "正常",
  "processTime": "2026-11-09T15:30:12.123"
}
```

以下是曲线的一条完整增量消息。同一个参数的两个点具有相同的毫秒时间，前端仍按数组顺序追加两个点。

```json
{
  "type": "delta",
  "stream": "curve",
  "sequence": 2,
  "complete": true,
  "retentionSeconds": 259200,
  "data": [
    {
      "deviceSatelliteId": 123,
      "telemetryCode": "TM001",
      "parameter": "电池电压",
      "parameterValue": 28.5,
      "status": "正常",
      "processTime": "2026-11-09T15:30:12.123"
    },
    {
      "deviceSatelliteId": 123,
      "telemetryCode": "TM001",
      "parameter": "电池电压",
      "parameterValue": 28.6,
      "status": "正常",
      "processTime": "2026-11-09T15:30:12.123"
    }
  ]
}
```

订阅请求无效时可能返回 `{"type":"error","message":"采集接口主键不能为空且必须大于零"}` 并关闭连接。关闭码 1008 时按订阅校验或登录状态处理。关闭码 1013 表示实时数据需重新同步，可退避后重连。连接销毁时取消待执行的重连任务。

## 前端更新规则

1. **帧列表**收到完整快照后替换列表。收到增量后按 `frameId` 合并，按 `frameOrder` 倒序排列。清理 `expiresAt <= Date.now()` 的帧，然后从尾部裁剪到最多 100 条且 `cachedBytes` 合计不超过 `frameCapacityBytes`。定时清理过期项，即使没有新消息也能移除过期帧。缓存快照为空时显示空列表。
2. **参数表格**收到完整快照后初始化已勾选行。增量按 `deviceSatelliteId + telemetryCode` 覆盖对应行，显示后端给出的文本或数值。值为 `0` 时正常显示，缓存未命中时值为空。将 `processTime` 转成 Unix 毫秒后加上 `retentionSeconds * 1000`，到期时清空对应值和状态。
3. **曲线**先画历史接口的 `times` 和 `values`，再将 `curve` 增量中的每个数值点按收到顺序追加。`processTime` 作横轴，`parameterValue` 作纵轴。同一毫秒的多个点逐个处理。历史结束到订阅生效之间的空档按实时展示约定不补发。
4. **重连**时帧和表格重新接收缓存快照，曲线保留已有绘图并标记中断，然后从新的实时消息继续绘制。实时转发走有界队列，掉线或过载期间的数据可能缺失。需要查看该段历史时可手动查询。
5. **时间转换**时，历史曲线 `times` 是 Unix 毫秒，帧的 `expiresAt` 也是 Unix 毫秒。实时 `processTime`、`time` 和 `receiveTime` 是不含偏移的业务时间，转换时使用服务约定的时区。

## 浏览器调用示例

下面的函数负责建立订阅、拼接分片快照和释放连接。页面根据订阅类型实现各自的数据更新回调。

```javascript
function subscribeTelemetry({ url, request, onSnapshot, onDelta, onError, onClose }) {
  const socket = new WebSocket(url);
  const snapshotRows = [];
  let disposed = false;

  socket.onopen = () => {
    // 连接打开后一次性提交令牌和订阅范围。
    if (!disposed) socket.send(JSON.stringify(request));
  };

  socket.onmessage = ({ data }) => {
    if (disposed) return;
    const message = JSON.parse(data);

    if (message.type === 'snapshot') {
      // 收齐所有快照分片后再更新页面。
      snapshotRows.push(...message.data);
      if (message.complete) {
        onSnapshot(snapshotRows.splice(0), message);
      }
    } else if (message.type === 'delta') {
      onDelta(message.data, message);
    } else if (message.type === 'error') {
      onError(message.message);
    }
  };

  socket.onerror = () => {
    if (!disposed) onError('遥测 WebSocket 连接异常');
  };
  socket.onclose = event => {
    if (!disposed) onClose(event);
  };

  // 页面卸载、任务切换或重新勾选时调用，丢弃旧连接的迟到消息。
  return function dispose() {
    disposed = true;
    socket.close();
  };
}
```

正常帧调用时传入 `request: { accessToken, taskId, stream: 'normal', interfaceId }`。异常帧将 `stream` 改为 `abnormal`。曲线先等待历史请求结束并完成绘制，再用同一套任务和筛选条件调用该函数。曲线的 `onSnapshot` 用于更新订阅状态，空快照时保留已有曲线。

## 联调检查

- 帧页面未选接口时保持空状态，选中后才能发起请求。切换接口后列表只出现新接口的帧。
- 打开正常帧和异常帧两个页面，确认各自收到对应类型的快照与增量。
- 分别修改表格和曲线勾选，保存并重连后检查两边的参数范围。
- 曲线历史请求和 WebSocket 订阅使用相同的遥测类型。收到相同毫秒的多个实时点时逐点绘制。
- 页面退出后释放连接。断线重连后，帧和表格用新快照初始化，曲线标记实时中断。

[Apifox 导入文件](apifox-openapi.yaml)内含握手地址及消息定义。在 Apifox 新建 WebSocket 请求，连接后发送订阅 JSON。
