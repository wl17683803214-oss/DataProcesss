# 前端对接：Lua脚本公式管理与关联遥测

更新日期：2026-10-30。本文对应当前实现，替代此前公式试算和手动同步操作说明。

## 1. 本次变化

- 新增可选参数类型声明parameterTypes，支持把处理参数中的遥测代号替换为同帧原码整数。
- 不声明的旧Lua脚本继续按原有数值参数规则处理，默认值、参数顺序和结果格式不变。
- 移除试算接口、请求对象和页面操作。
- 移除公式管理的手动同步接口及按钮。导入、覆盖及删除事务提交后自动排队更新内部运行配置。
- 每个公式编号仍只保存一份脚本，同编号覆盖，无历史版本及启停状态。

本次不增加数据库字段或改变公式列表的响应字段。已完成旧结构简化升级的环境只需配套部署新版管理、处理服务；尚未建表或仍为历史版本结构的环境见[公式说明](lua-formulas/README.md)。

## 2. 通用规则

接口地址沿用网关前缀及登录认证方式。公式全系统共享，不传taskId。普通响应为code、message、data，成功code=200；参数错误返回HTTP 400及中文message。文件导出成功返回附件二进制，失败仍使用JSON错误响应。

编号是1至20位数字组成的字符串，不能转JavaScript数值，以免丢失前导零。页面只有编号、名称、创建时间、更新时间等元数据，不展示版本或启用状态。修改源码采用“导出、修改文件、重新导入”，没有在线源码保存接口。

本地Lua处理用于PDXP本地处理链路；开启RPC的接口沿用远程处理。原有的其他模块导入预检查功能不受本次移除公式试算的影响。

## 3. 接口清单

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | /processing/formulas | 分页查询公式 |
| POST | /processing/formulas/import | 单个Lua或ZIP导入，同编号覆盖 |
| GET | /processing/formulas/export | 导出指定编号当前脚本 |
| GET | /processing/formulas/export-zip | 指定编号或全部导出 |
| POST | /processing/formulas/batch-delete | 批量删除无引用公式 |

完整请求契约见[Apifox文件](apifox-openapi.yaml)。前端不再提供试算弹窗或“同步运行配置”按钮，不调用已移除的专用接口。

## 4. 分页查询

请求示例：GET /processing/formulas?pageNum=1&pageSize=20&code=400&name=相加。

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| code | 字符串 | 否 | 编号精确匹配，空白不筛选 |
| name | 字符串 | 否 | 名称模糊匹配，空白不筛选 |
| pageNum | 整数 | 否 | 默认1，必须大于0 |
| pageSize | 整数 | 否 | 默认20，范围1至200 |

同时传code、name时同时筛选。更改筛选后页码重置为1。绑定data.records和data.total，行键及勾选键使用code。

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "pageNum": 1,
    "pageSize": 20,
    "total": 1,
    "records": [
      {
        "code": "400",
        "name": "两个关联遥测原码相加",
        "createTime": "2026-10-30T10:00:00",
        "updateTime": "2026-10-30T10:20:00"
      }
    ]
  }
}
```

createTime保留首次导入时间，updateTime表示内容最近修改时间。记录不返回source、version或parameterTypes。公式选择器用编号或名称分页搜索，不能只读取第一页就判定其他编号不存在。

## 5. 导入与覆盖

POST /processing/formulas/import，multipart/form-data字段file。使用FormData并由浏览器生成边界，携带现有登录凭证。

| 项目 | 限制 |
| --- | --- |
| 文件类型 | 单个.lua或只含Lua文件的.zip |
| 编码 | UTF-8 |
| 单脚本 | 最大64KB |
| 上传文件 | 最大8MB |
| 批次数量 | 最多100个公式、200个ZIP条目 |
| 重复编号 | 同一包内编号不能重复，以脚本内部code为准 |

导入先校验脚本语法、编号、入口及可选参数声明，任一项失败整批不保存。相同编号覆盖当前源码；相同源码重复导入不改变更新时间。

```json
{
  "code": 200,
  "message": "操作成功",
  "data": [
    {
      "code": "400",
      "name": "两个关联遥测原码相加",
      "createTime": "2026-10-30T10:00:00",
      "updateTime": "2026-10-30T10:20:00"
    }
  ]
}
```

成功data为数组，不是分页对象。成功后刷新列表及勾选状态，提示“导入成功，后台配置更新已提交”。不表示运行快照已经更新完成，不增加手动同步步骤。失败时展示message，不能展示部分成功。

示例：[关联原码相加脚本](lua-formulas/400_关联遥测原码相加.lua)、[全部示例包](lua-formulas/处理公式示例.zip)。

## 6. 单个与批量导出

- 单个：GET /processing/formulas/export?code=400，附件名400.lua。
- 勾选：GET /processing/formulas/export-zip?codes=100,400，codes用逗号分隔，附件名formulas.zip。
- 不传codes表示全部当前公式，数量仍须为1至100个；超过100时按编号选择导出。
- 勾选为空时禁用勾选导出，不能误调用全部导出。
- 无版本参数。指定不存在编号返回错误。

使用带登录凭证的二进制下载请求。若跨域环境读不到Content-Disposition，可使用上述已知文件名。失败时读取JSON中的message，不将错误JSON存为.lua或.zip。

## 7. 批量删除

POST /processing/formulas/batch-delete，JSON请求：

```json
{"codes":["100","400"]}
```

单次1至100项，重复编号只计一次。任一编号不存在，或被任意任务的未删除参数解析配置引用时整批不删。成功响应data为实际删除数：

```json
{"code":200,"message":"操作成功","data":2}
```

错误示例：

```json
{"code":400,"message":"以下公式被参数配置引用，整批未删除：400"}
```

成功后清理勾选、刷新列表；删除后当前页为空且页码大于1时回到上一页。失败时不先从页面移除部分行。删除提交后后台自动更新运行配置，页面提示“已删除，后台配置更新已提交”；不需要再调用同步。

## 8. 参数解析配置的关联输入

沿用参数编辑接口中的formulaType、processParam、decimalPlaces等字段，不增加关联遥测请求对象。processParam作为普通文本提交，不做全局“只能填数字”的校验。具体哪些位置是数值、哪些是代号，由Lua脚本声明决定。

示例400的参数配置片段：

```json
{"formulaType":"400","processParam":"TM002/TM003"}
```

这是字段片段，不能代替原参数编辑接口要求的完整请求。保留并提交其他业务字段。公式400要求恰好两个遥测代号，用斜线分隔；不添加@前缀，不在前端把代号换算成数值。

脚本声明含义：

| 参数类型 | 配置中填写 | 后端实际传入Lua |
| --- | --- | --- |
| number | 数值常量，例如2或0.02 | 原有十进制数值文本 |
| telemetry_raw | 同帧遥测代号，例如TM002 | 该代号原码按小端无符号整数解析后的十进制文本 |

声明在脚本定义层，加载时读取，不是写在calculate计算函数里。没有声明或未声明的位置默认number。声明类型错误时拒绝导入，不静默降级。列表接口没有声明字段，前端不得自行猜测类型或根据代号是否含数字判断。

formulaType为空仍正常输出原码，不因无公式告警。formulaDesc仅为历史描述，不参与计算。原100、109、300、301、302、303脚本不需要修改；旧数值参数默认规则继续有效。

## 9. 关联公式400的行为与缺失处理

公式400不使用当前目标遥测的原码计算，而是将processParam指定的两项原码相加。例如：

| 代号 | 当前帧原始字节 | 小端无符号原码 |
| --- | --- | --- |
| TM002 | 05 | 5 |
| TM003 | 0A 00 | 10 |

目标结果为15。取值来自同一接口、同一帧，不是其他遥测的处理结果，不查数据库或历史缓存。真实原码为0时正常参与相加。

后台先取齐原码，再按原配置顺序计算，因此能引用排在后面的字段。同帧有重复代号时取序号靠后的字段原码，与既有消息保留最后一项的规则一致。被引用遥测自身公式失败，只要原码能提取，仍可用于原码关联。当前目标字段仍按原配置位宽占用数据，不新增零位宽虚拟参数规则。

以下情况使当前目标参数保留BINARY原码、不生成计算值，并记录“参数处理失败”告警，同帧其他可处理参数继续：

- processParam为空，或少填一个必需的遥测代号。
- 中间空项，例如TM002/。
- 遥测代号没有在当前帧的参数配置原码索引中找到。
- 关联原码数值超出允许范围，或公式结果不合法。

不能用0、当前目标原码或上帧值替代缺失引用。告警包含目标遥测、公式编号、缺失参数位置和关联代号。前端值为空时显示“—”，不能强制变成0。修正参数配置或脚本后，内部配置更新生效，后续计算正常会自动恢复处理告警；历史失败数据不补算。

如果整帧原码不足、位宽越界等导致原码提取失败，沿用现有异常帧处理，不属于可用其他值兜底的关联缺失。

## 10. 后台更新与验收

导入、覆盖及删除提交后自动复用现有内部配置同步队列。启动采集接口仍会加载数据库脚本；每帧只使用已加载快照，不逐条查数据库。已开始的帧完成原快照，后台更新完成后后续数据使用当前脚本。保存成功与运行更新完成不是同一状态，目前没有单独进度查询接口；后台失败通过已有运行日志和告警定位。

前端验收：

| 场景 | 预期 |
| --- | --- |
| 分页、筛选、空页回退 | records、total和页码正确 |
| 旧脚本导入及数值参数 | 不要求补声明，不改变默认值 |
| 上传带错误声明的脚本 | 导入失败，整批不保存 |
| 同编号覆盖 | 一条记录，创建时间保留，修改时间更新 |
| 上传和删除成功 | 自动提交后台更新，无额外同步按钮 |
| 勾选导出、下载错误 | 不误触发全部导出，错误JSON不保存为附件 |
| 被引用或不存在编号的批量删除 | 整批不删，展示对应编号 |
| 400填写TM002/TM003 | 按同帧原码相加，前后字段顺序不影响取值 |
| 缺少代号、未知代号 | 目标无计算值并产生告警，其他参数继续 |
| 关联原码等于0 | 正常参与计算，不能判为缺失 |
| 64位原码及带前导零代号 | 前端不转数值、不改变字符或字节序 |
| 旧试算及手动同步入口 | 页面移除，不再发起请求 |

本文按现有代码及契约整理，数据库升级、服务部署和真实设备联调不由文档更新自动完成。

## 重复遥测代号支持

同一任务、同一设备卫星的参数允许填写相同telemetryCode，序号tableIndex仍必须唯一。Excel、TXT导入以及批量编辑均遵循此规则。参数配置表格用参数主键id作为行键，不能用telemetryCode作为唯一行键，也不能在前端拦截重复代号。

同帧输入5项、其中两项同代号时，处理结果保留4项，序号靠后的项覆盖前项，累计一次去重并产生已有的数据去重告警。两个值相同也属于重复。关联公式通过代号取原码时同样取最后一项。

处理后表格、曲线和勾选仍按设备及遥测代号识别，同代号配置共用一份勾选及最终值，不展示两条相同结果。修改其中一条代号时，仍有其他同代号记录的原勾选继续保留。

已部署环境需执行sql/20261030_allow_duplicate_telemetry_codes.sql解除旧唯一索引，尚未执行数据库迁移。新库使用更新后的business_schema.sql。当前PDXP本地处理的tm_type仍固定为TM_TYPE_DEVICE_TM，实时和延迟测试数据暂不制作。
