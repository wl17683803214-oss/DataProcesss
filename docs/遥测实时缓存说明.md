# 遥测实时缓存与 WebSocket

解析完成后，结果分发器将只读消息和原码引用交给有界实时队列。后台按批组装整帧和遥测值，写入 Redis 快照，再由独立发布队列发送本批增量。入库和消息发送使用各自的原有分支。

| 配置项（telemetry-realtime） | 默认值 | 含义 |
| --- | ---: | --- |
| retention-seconds | 259200 | 正常帧、异常帧和每个遥测最新值共用的保留秒数 |
| frame-capacity-bytes | 4194304 | 每任务、每接口、每种帧状态的序列化记录字节上限 |
| queue-capacity | 256 | 等待实时组装的解析结果数 |
| max-pending-parameters | 3000000 | 等待与正在组装的参数点额度 |
| max-pending-frame-bytes | 16777216 | 等待与正在组装的完整帧原码字节额度 |
| flush-interval-millis | 50 | 组装线程的合批周期 |
| push-queue-capacity | 64 | 处理端发布队列及管理端接收队列各自的等待批数 |

正常帧和异常帧按任务、接口、状态分开，每条完整记录只写一次。列表按写入顺序保留，超过字节上限时从尾部逐条淘汰。帧到期后从查询结果剔除，在读写时清理到期记录，停止写入后列表键整体过期。前端快照最多返回最新 100 条。`cachedBytes` 计入序列化记录、过期时间和顺序前缀，Redis 管理开销另计。

每个最新参数独立过期，时间由该参数的最新更新时间计算。组装阶段按对象、遥测类型和代号合并快照值，推送增量保留批内所有参数点。表格订阅只展示勾选范围的最新值，曲线订阅逐点发送有限数值。

两服务使用同一个 Redis 部署并配置相同的 `key-prefix`、`retention-seconds`、`frame-capacity-bytes`。当前前缀为 `telemetry:live:v2:`。修改后重启服务。已有旧版缓存由其原有过期时间回收。

连接先发送缓存快照，之后按连接队列顺序处理增量。帧的缓存写入顺序用于排除快照之前的旧帧，也用于前端排序。管理服务按任务、接口、状态或勾选范围过滤。发送队列超限会关闭对应连接。上游队列超限或发布失败时，后续可用时通知重新同步。Redis Pub/Sub 不提供离线重放。帧和参数初始快照及前端处理见 [前端对接文档](前端对接-遥测实时轮询.md)。
