# 清除当前页面遥测参数筛选

## 1. 接口与清除范围

新增 `POST /processing/telemetry-filter-selection/clear`，用于一次取消当前页面或当前可视化组件中的全部遥测参数勾选。

范围由 `taskId + selectionType + targetId` 共同确定，与筛选树、单项勾选接口保持一致。

| 当前使用位置 | selectionType | targetId | 清除范围 |
| --- | --- | --- | --- |
| 处理后数据表格 | 1 | 固定传 `0` | 当前任务处理后表格的全部参数勾选 |
| 处理后数据曲线 | 2 | 固定传 `0` | 当前任务处理后曲线的全部参数勾选 |
| 数据可视化表格 | 3 | 当前实时数据组件的 `widgetId` | 该组件的全部参数勾选 |
| 数据可视化曲线 | 4 | 当前实时曲线组件的 `widgetId` | 该组件的全部参数勾选 |

- 清除覆盖该范围内全部设备、卫星、系统和参数，包括尚未展开、尚未加载，以及不在当前搜索结果中的已选参数。
- 处理后表格和曲线分别清除；不同任务、不同场景及不同可视化组件之间互不影响。
- 可视化场景的一次调用只处理一个组件。按钮应放在对应组件的参数筛选区域，不应把它解释成清除整个可视化页面的所有组件。
- 处理后数据页面的勾选按任务共享。同任务其他用户查看对应场景时也会看到清除后的状态。可视化组件只能操作当前用户自己、当前任务中的对应类型组件。
- 接口只取消参数勾选，不删除参数配置和历史遥测数据，也不清除搜索输入、设备选择、遥测类型等其他查询条件。

## 2. 参数从哪里取

直接从当前 `GET /processing/telemetry-filter-tree` 请求中复用 `taskId、selectionType、targetId`，不需要新增查询。

| 参数 | 类型 | 必填 | 来源与要求 |
| --- | --- | --- | --- |
| `taskId` | 字符串 | 是 | 当前任务编号，不能为空或空白 |
| `selectionType` | 整数 | 是 | 当前筛选树使用的勾选场景，仅支持 `1、2、3、4` |
| `targetId` | 整数 | 是 | 固定页面传 `0`，可视化场景传对应组件的 `widgetId` |

`selectionType` 的中文选项可复用 `GET /processing/findData` 响应中的 `data.selectionType`。

注意 `selectionType` 和组件类型 `widgetType` 是两组不同的枚举：实时数据组件的 `widgetType=2` 对应 `selectionType=3`；实时曲线组件的 `widgetType=1` 对应 `selectionType=4`。

## 3. 请求与响应

使用现有登录认证，请求头携带 `Authorization: Bearer 登录令牌` 和 `Content-Type: application/json`。三个业务参数全部放在 JSON 请求体中，不需要放在查询参数中。

清除处理后表格：

```http
POST /processing/telemetry-filter-selection/clear
Content-Type: application/json
Authorization: Bearer 登录令牌

{
  "taskId": "TASK-20260908-001",
  "selectionType": 1,
  "targetId": 0
}
```

清除某个可视化实时数据组件：

```json
{
  "taskId": "TASK-20260908-001",
  "selectionType": 3,
  "targetId": 205
}
```

示例任务编号及组件 ID 需替换成页面实际值。不提交 `parseRuleId、checked、deviceSatelliteId、systemId、telemetryCode`。

成功响应为 HTTP 200：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": true
}
```

当前范围没有已选参数、重复点击清除时，仍返回上述成功结果。`data` 是布尔值，不是清除数量。

## 4. 页面接入流程

1. 点击当前页面或组件中的“清除全部勾选”按钮，复用该范围的三个参数发起请求。
2. 发起前先等待该范围内已提交的单项勾选保存完成；请求期间禁用当前范围的勾选操作及清除按钮，避免较晚完成的保存请求重新勾选参数。
3. 收到成功响应后，清空当前范围的已选参数缓存和树勾选状态，包括已加载分支、搜索结果及尚未展示的缓存。通过程序取消树勾选时，应抑制单项勾选事件，避免逐条调用保存接口。
4. 刷新当前筛选树的已加载节点或搜索结果。表格重新调用 `GET /processing/processed`，曲线重新调用 `GET /processing/processed/curve`，继续使用相同的三个范围参数。
5. 清除当前范围的旧表格行、曲线及图例，处理好清除前发出的轮询和加载请求，丢弃过期响应，避免旧数据再次覆盖空状态。清除后对应查询返回空数组，可显示“暂无已选参数”。
6. 请求失败时保留当前勾选状态，显示后端 `message`；请求结束后恢复操作按钮。清除成功但刷新失败时，应提示刷新失败并允许重试加载。

## 5. 常见失败响应

以下业务校验失败返回 HTTP 400，并且不会清除任何记录：

| 情况 | message |
| --- | --- |
| `taskId` 缺失或空白 | 试验任务编号不能为空 |
| `selectionType` 缺失 | 参数勾选类型不能为空 |
| `targetId` 缺失 | 勾选目标主键不能为空 |
| 任务不存在 | 目标试验任务不存在 |
| 场景编码不在 `1、2、3、4` 内 | 参数勾选类型无效 |
| 处理后数据页面的 `targetId` 不为 `0` | 处理后数据页面的目标主键必须为零 |
| 可视化场景的 `targetId` 小于等于 `0` | 数据可视化组件主键不能为空 |
| 组件不存在、属于其他任务或用户，或组件类型不匹配 | 当前任务下不存在匹配的可视化组件 |

当多个字段同时无效时，以实际返回的首个校验错误为准。

```json
{
  "code": 400,
  "message": "当前任务下不存在匹配的可视化组件"
}
```

## 6. 联调检查

1. 在处理后表格和曲线分别勾选参数，清除表格后检查曲线勾选仍保留。
2. 在同一范围下跨设备、跨系统勾选多个参数，只搜索其中一个代号后清除，检查该范围下全部已选参数均已取消。
3. 在两个同类型可视化组件中分别勾选参数，清除其中一个，检查另一个组件仍保留勾选。
4. 在其他任务中保留勾选，清除当前任务后检查其他任务未受影响。
5. 清除后再次清除应成功；重新勾选一个参数后，刷新树及数据应能正常显示。
6. 提交其他用户的组件 ID、错误任务、错误组件类型或非法场景编码，检查返回 HTTP 400，且原勾选保持不变。

Apifox 导入文件：`docs/apifox-openapi.yaml`，导入更新后可按接口名称“清除当前页面全部遥测参数勾选”查找。
