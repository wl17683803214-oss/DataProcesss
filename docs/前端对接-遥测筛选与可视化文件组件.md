# 前端对接：遥测筛选与可视化文件组件

本文对应本次后端改动。接口仍使用管理服务现有的登录令牌和统一响应格式；所有涉及试验任务的请求都要传当前 `taskId`。完整接口定义见同目录的 `apifox-openapi.yaml`。

## 一、勾选场景

遥测参数的勾选按“任务 + 场景 + 目标对象 + 设备卫星 + 遥测代号”分别保存。处理后数据表格与曲线不再互相影响，不同可视化组件也不共用勾选结果。

| `selectionType` | 中文名称 | 使用位置 | `targetId` |
| --- | --- | --- | --- |
| `1` | 处理后数据表格 | 数据处理页最新值表格 | 固定为 `0` |
| `2` | 处理后数据曲线 | 数据处理页最近曲线 | 固定为 `0` |
| `3` | 数据可视化表格 | 类型为 `2` 的实时数据组件 | 该组件的 `id` |
| `4` | 数据可视化曲线 | 类型为 `1` 的实时曲线组件 | 该组件的 `id` |

`GET /processing/findData` 和 `GET /visualization/findData` 都会在 `data.selectionType` 返回上述编码和中文名称。可视化枚举的 `data.widgetType` 另增加 `5 文件表格`；原有 `4 载荷图像` 用于图片列表。

固定页面的勾选仍由同一任务共享。可视化组件属于创建它的用户，组件场景的查询和保存会校验当前用户、任务及组件类型。

## 二、遥测参数筛选树

`GET /processing/telemetry-filter-tree` 必须传 `taskId`、`selectionType`、`targetId`。接口按需展开，不分页，也不返回 `children` 字段。

| 操作 | 查询参数 | 返回内容 |
| --- | --- | --- |
| 加载第一层 | `taskId`、`selectionType`、`targetId` | 设备卫星节点 |
| 展开设备 | 再传 `deviceSatelliteId` | 该设备直属参数、根系统 |
| 展开系统 | 再传 `deviceSatelliteId`、`systemId` | 该系统直属参数、子系统 |
| 搜索遥测代号 | 再传 `telemetryCode` | 当前任务下代号**完全相等**的参数节点 |

搜索时不能同时传 `deviceSatelliteId` 或 `systemId`。`telemetryCode` 不做模糊或前缀匹配；同一代号若出现在多个设备下，会返回多条参数节点。

例如，展开数据可视化表格组件 `205` 中的设备 `12`：

```http
GET /processing/telemetry-filter-tree?taskId=TASK-001&selectionType=3&targetId=205&deviceSatelliteId=12
```

```json
{
  "code": 200,
  "message": "操作成功",
  "data": [
    {
      "id": 81,
      "label": "电压/TMK1001",
      "nodeType": "parameter",
      "nodeTypeName": "遥测参数",
      "selectable": true,
      "checked": true,
      "hasChildren": false
    },
    {
      "id": 21,
      "label": "测控系统",
      "nodeType": "system",
      "nodeTypeName": "所属系统",
      "selectable": false,
      "checked": false,
      "hasChildren": true
    }
  ]
}
```

只有 `nodeType=parameter` 的节点可以勾选，其 `id` 是参数解析配置主键。搜索结果的参数节点还会带 `deviceSatelliteId`、`deviceSatelliteName`，已分类参数会带 `systemName`（完整系统路径）；未分类时不返回 `systemName`。`checked` 已按本次请求的场景计算。

## 三、即时保存勾选

`POST /processing/telemetry-filter-selection/update`

```json
{
  "taskId": "TASK-001",
  "parseRuleId": 81,
  "checked": true,
  "selectionType": 3,
  "targetId": 205
}
```

`checked=true` 表示勾选，`false` 表示取消。每次点击参数复选框即可调用一次，不需要等待整棵树提交。成功时返回 `data: true`。`parseRuleId` 取参数节点的 `id`，不要传系统或设备节点的 `id`。固定页面把 `targetId` 设为 `0`；可视化页面先创建组件，再使用创建接口返回的组件 ID。

## 四、处理后数据表格和可视化实时数据表格

两个页面共用最新值接口：

```http
GET /processing/processed?taskId=TASK-001
GET /processing/processed?taskId=TASK-001&selectionType=3&targetId=205
```

第一种写法默认使用 `selectionType=1、targetId=0`。第二种用于数据可视化表格组件，必须传该组件 ID。接口自动查询对应场景已勾选的参数；不传设备主键、遥测代号或分页参数。

```json
{
  "code": 200,
  "message": "操作成功",
  "data": [
    {
      "deviceSatelliteId": 12,
      "telemetryCode": "TMK1001",
      "parameter": "电压",
      "parameterValue": 41.2,
      "status": "加电",
      "processTime": "2026-09-29T10:30:15"
    }
  ]
}
```

每个已勾选参数最多返回一条最新值。参数已勾选但还没有历史数据时，仍返回该参数，`parameterValue`、`status`、`processTime` 为空。`status` 是处理后的中文状态名称。

## 五、处理后曲线和可视化曲线

两个页面共用最近曲线接口：

```http
GET /processing/processed/curve?taskId=TASK-001
GET /processing/processed/curve?taskId=TASK-001&selectionType=4&targetId=206
```

第一种写法默认使用 `selectionType=2、targetId=0`。第二种用于数据可视化曲线组件。每个已勾选参数分别查询最近最多 `120` 个原始点，不限制时间范围。

```json
{
  "code": 200,
  "message": "操作成功",
  "data": [
    {
      "deviceSatelliteId": 12,
      "telemetryCode": "TMK1001",
      "parameter": "电压",
      "times": [1790658600000, 1790658601000],
      "values": [41.2, 41.3]
    },
    {
      "deviceSatelliteId": 12,
      "telemetryCode": "TMK1002",
      "parameter": "电流",
      "times": [1790658600500],
      "values": [2.6]
    }
  ]
}
```

**每条曲线有自己的 X 轴。** `times[i]` 与同一条曲线的 `values[i]` 对应；`times` 是按时间升序排列的 Unix 毫秒时间戳。不同曲线的时间点和点数可能不同。没有历史数据的已勾选参数返回空 `times`、`values` 数组。

## 六、可视化组件类型及创建顺序

可视化组件沿用 `POST /visualization/widgets/create`，请求中的 `widgetType` 如下：

| `widgetType` | 中文名称 | 本次数据来源 |
| --- | --- | --- |
| `1` | 实时曲线 | `/processing/processed/curve`，`selectionType=4` |
| `2` | 实时数据 | `/processing/processed`，`selectionType=3` |
| `3` | 实时告警 | 原有逻辑，本次未改 |
| `4` | 载荷图像 | 图片文件分页接口 |
| `5` | 文件表格 | 非图片文件分页接口 |

组件创建成功后，响应 `data` 是组件 ID。实时曲线和实时数据组件按顺序调用“创建组件 → 用组件 ID 加载筛选树 → 保存勾选 → 查询曲线或最新值”。新组件不再自动生成任务下所有参数的数据项；可视化遥测参数应通过本次的筛选树选择。

现有 `GET /visualization/widgets/{widgetId}/items` 只返回组件已有数据项。遥测参数项的 `isSelected` 读取统一勾选结果；非遥测数据项仍使用自身勾选状态。已有的 `/visualization/items/selected` 对遥测参数项也会写入统一勾选结果。删除组件后，该组件的遥测勾选会一起清理。

## 七、图片与文件表格

图片组件和文件表格组件共用接口，前端无需再传图片/文件分类：

```http
GET /visualization/widgets/207/files?taskId=TASK-001&pageNum=1&pageSize=20
```

`widgetId` 是路径中的组件 ID。`taskId` 必填；`pageNum` 默认 `1`，`pageSize` 默认 `20`、最大 `200`。组件类型为 `4` 时，只查询 `jpg、jpeg、png、gif、bmp、webp、tif、tiff` 后缀；类型为 `5` 时查询其他后缀及无后缀文件。只返回已上传到 MinIO 的 FEP 文件（处理状态 `2` 或 `3`），按接收完成时间倒序排列。接口会校验组件属于当前任务和登录用户。

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "pageNum": 1,
    "pageSize": 20,
    "total": 1,
    "records": [
      {
        "id": 128,
        "interfaceId": 6,
        "interfaceName": "载荷文件接收接口",
        "fileName": "载荷图像001.png",
        "fileType": "png",
        "fileLength": 245760,
        "fileUrl": "http://10.126.100.61:9002/fep-files/example.png",
        "completedTime": "2026-09-29T10:30:15"
      }
    ]
  }
}
```

`fileLength` 单位为字节；`fileType` 是文件名的小写后缀，可能为空。`interfaceName` 来自采集接口，接口记录不存在时可能为空。不返回设备卫星字段，也不按设备卫星筛选。图片预览和文件下载使用 `fileUrl`；浏览器必须能够访问部署环境配置的对象存储对外地址。文件类别依据后缀判定，不校验文件实际内容。

## 八、前端需要修改的位置

1. 处理后数据表格的筛选树和保存请求传 `selectionType=1、targetId=0`；曲线传 `selectionType=2、targetId=0`，分别维护复选框状态。
2. 可视化实时数据组件传 `selectionType=3、targetId=组件ID`；可视化曲线传 `selectionType=4、targetId=组件ID`。两类组件复用处理后数据、曲线查询接口。
3. 参数筛选树的搜索框按**完整遥测代号**查询；搜索时清除设备和系统展开参数。
4. 创建图片组件使用 `widgetType=4`；创建文件表格使用 `widgetType=5`。两者使用同一个文件分页接口，按 `data.records` 渲染。
5. 用 `GET /processing/findData` 或 `GET /visualization/findData` 获取勾选场景中文名称和组件类型中文名称，不在前端自行翻译编码。

后端代码和 Apifox 文件已经更新；现有环境使用新接口前，需要先执行 `sql/business_schema.sql` 中新增的勾选场景与索引升级语句。数据库及 MinIO 地址的部署联调尚未完成。
