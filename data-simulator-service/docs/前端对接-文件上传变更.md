# 模拟源文件上传：前端变更说明

## 1. 页面需要改什么

- 新建、编辑模拟源时，把“文件路径”文本输入框改为“上传文件”控件，PDXP和FEP都使用该控件。
- 选择文件后立即上传，成功后展示文件名和文件大小。
- 上传进行中禁用“保存”；新建时未上传成功不能保存。
- 不再让用户输入服务器路径，不提交浏览器本地路径。
- 协议、目标地址、目标端口、发送间隔、是否循环及其他参数的交互保持现有逻辑。

## 2. 上传接口

`POST /simulator/files/upload`

沿用模拟源服务现有请求地址和代理配置。

请求类型：`multipart/form-data`。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `file` | 文件 | 是 | 用户选择的单个文件 |

使用 `FormData`，不要把文件转成JSON或Base64。由浏览器生成带有boundary的请求头，上传请求不要套用强制JSON请求头。

```javascript
const formData = new FormData();
formData.append("file", selectedFile);

const response = await fetch("/simulator/files/upload", {
  method: "POST",
  body: formData
});
const result = await response.json();
if (!response.ok || result.code !== 200) {
  throw new Error(result.message || "文件上传失败");
}

// 上传成功后才替换表单原来的有效文件。
formModel.filePath = result.data.filePath;
uploadedFileName = result.data.fileName;
uploadedFileSize = result.data.fileSize;
```

以上示例使用原生请求；实际项目可沿用已有上传请求封装及鉴权请求头。

成功响应：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "fileName": "图片.png",
    "fileSize": 239977,
    "filePath": "/DataPro/simulator/data/simulator/uploads/file-123456789/图片.png"
  }
}
```

| 返回字段 | 前端用途 |
|---|---|
| `fileName` | 展示文件名 |
| `fileSize` | 展示文件大小，原始单位为字节，可换算为KB或MB |
| `filePath` | 隐藏保存在表单中，创建或修改时原样提交 |

不要照抄示例中的路径，不要对返回路径进行拼接、URL编码或分隔符转换。`filePath`不是下载地址，不能用于图片预览或超链接下载。

## 3. 新建和保存

调用顺序：选择文件 → 上传成功 → 保存模拟源。

创建仍调用 `POST /simulator/sources/create`，修改仍调用 `POST /simulator/sources/update`，继续使用JSON请求。原有字段保留，`filePath`改为上传接口返回值。

例如FEP新建请求：

```json
{
  "sourceName": "文件模拟源一",
  "transferProtocol": 3,
  "transferType": 2,
  "filePath": "/DataPro/simulator/data/simulator/uploads/file-123456789/图片.png",
  "targetHost": "127.0.0.1",
  "targetPort": 19003,
  "sendIntervalMillis": 10,
  "loopEnabled": 0
}
```

保存请求只增加或替换原有的 `filePath` 值，**不要提交 `fileName`、`fileSize`、原始文件对象、上传状态或进度等页面字段**。PDXP继续提交原来的 `pdxp` 参数，FEP仍不提交 `pdxp`。

上传成功不代表模拟源已保存或开始发送，保存、启动继续使用原有操作。

## 4. 编辑和回显

1. 从详情接口读取原来的 `filePath`，不要求用户重新上传。
2. 文件名从路径最后一段提取，兼容 `/` 和 `\` 两种分隔符；旧记录没有文件大小时，不展示大小。
3. 没有替换文件时，保存原来的 `filePath`。
4. 替换文件时，上传成功后才更新 `filePath`；上传失败或取消本次选择，保留之前有效的文件。
5. 同时只能有一个文件正在上传，或确保较早请求的返回结果不会覆盖用户后来选择的文件。

列表和详情若原先展示文件路径，可改为展示文件名。同名文件可以分别上传，不要求前端改名。

## 5. 提示和异常处理

- 上传不限制扩展名，不要只允许图片或`.dat`文件。
- 默认单文件上限1GB，最终以上传接口校验结果为准。
- 允许选择0字节文件用于FEP；PDXP仍要求文件非空、大小为输入帧长度的整数倍。
- 文件名不能携带目录、路径或非法字符；FEP文件名还受协议64字节限制，按后端启动提示处理。
- 建议提示：“请上传模拟数据文件，上传成功后可保存；启动时检查协议格式。”

| HTTP状态码 | 前端处理 |
|---|---|
| 200且`code=200` | 更新文件名、大小和表单中的`filePath` |
| 400 | 展示`message`，保留表单和此前有效文件 |
| 413 | 提示上传文件或请求超限，允许重新选择文件 |
| 415 | 检查上传请求是否使用`multipart/form-data` |
| 500 | 展示`message`，允许用户重新上传 |
| 网络异常或非JSON响应 | 提示上传失败，允许重试；不要将本次选择标为上传成功 |

取消整个表单、替换文件或删除模拟源时，不额外调用文件删除接口。当前没有上传文件删除、下载或目录浏览入口。
